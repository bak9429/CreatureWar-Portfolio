# QA · 트러블슈팅 사례

> 기술 스택 및 작업 환경 전환 과정의 실험 기록입니다. 검증되지 않은 해결은 '미검증'으로 표기했습니다.

## 사례 1 — 단일 개체 입력 규칙 위반

**증상:** 4면도/아틀라스가 한 이미지에 들어가 3D 생성 결과에서 여러 형상이 겹치거나, 특정 노드 이미지의 이름과 형태가 달라짐.  
**원인:** 4면도를 한 장으로 묶어 Trellis 입력에 사용한 점, 작은 셀을 잘라 내면서 경계와 구조가 훼손된 점.  
**개선:** 노드별 단일 개체 PNG 입력을 우선으로 지정. BODY·HEAD 별도 생성 및 QC 단계 도입.  
**결과:** 입력 구조의 문제를 분리·진단했으나 모든 모델의 형상 정확도는 아직 검증되지 않음.

## 사례 2 — 생물 계통별 실루엣 중복

**증상:** 박쥐형에 날개 연결 구조가 없고, 곰·소·코끼리 계통 간 형상 차이가 미약한 등 노드 의미와 에셋의 불일치.  
**원인:** 대량 시트 생성 방식에서 노드별 특징을 강하게 통제하지 못함.  
**개선:** 노드 ID와 해부학적 요구사항을 명시하고, 중복 여부 및 역할 수행 기관을 체크리스트로 검토.  
**결과:** 일괄 생성본은 최종 자산에서 제외. 재작업/실물 검증 필요.

## 사례 3 — Trellis.cpp 모델 경로 오류

**증상:** `gguf_init_from_file: failed to open GGUF file 'models/birefnet.gguf'` 이후 연속 실패.  
**원인:** 자동 실행에서 CLI 실행 파일 위치만 지정하고 GGUF 모델 경로를 별도 설정하지 않음.  
**개선:** `--models` 경로 설정, 사전 파일 확인, 테스트 1건 수행 후 전체 배치 처리, 실패 시 즉시 중단하도록 스크립트 변경.  
**결과:** 오류 원인 및 배치 스크립트 수정은 확인. 실 사용자 Windows 환경에서 후속 성공 로그는 공개 자료에 없으므로 성공을 단정하지 않음.

## 현재 QA 게이트

| 검사 항목 | 통과 기준 | 공개 자료로 확인된 상태 |
|---|---|---|
| 데이터 무결성 | T0~T2 ID 고유/부모 존재 | 자동검증 포함 |
| 입력 이미지 | 하나의 PNG = 하나의 명확한 물체 | 일부 시험 입력, 전량 QC 미완료 |
| 해부학적 정합성 | 파츠 구조·다리 수·실루엣 일치 | 전량 QC 미완료 |
| 모델 생성 | GLB 생성 및 정상 열기 | 일부 실험, 전량 QC 미완료 |
| BODY/HEAD 교체 | 목 접합면 대응 및 위치 일치 | 미검증 |
| Unreal 연동 | 엔진 내 애셋 확인·실행 | 공개된 증빙 없음 |

> 트러블슈팅은 향후 개선 근거로 공개하며, QA 미통과를 성공 사례로 포장하지 않습니다.
